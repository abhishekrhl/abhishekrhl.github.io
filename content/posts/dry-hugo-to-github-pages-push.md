## The local `public/` folder: sandbox only

After completing kit QA and the dry Hugo build (post 11), the `public/` directory contains static files waiting for inspection. They are a snapshot of content generated by Ollama on Apple Silicon, often via MLX audio or other local models, but they have zero authority until a human validates them.

The distinction is critical: the local build is for iteration and error-checking; GitHub Pages deployment is the moment of truth. We do not deploy directly from the Hugo-generated `public/` folder. Instead, we treat those files as raw material. The agent's role ends once it compiles static HTML, CSS, and JavaScript. From that point forward, human oversight becomes mandatory. This separation ensures no unverified code or hallucinated data reaches the global edge network.

## The `_redirects` file: manual audit required

Before pushing to GitHub Pages, the `_redirects` configuration file demands a rigorous human checklist. This file dictates URL mappings between old and new structures, often generated by Hugo's build process or migration scripts. An agent might suggest a redirect based on pattern matching, but it cannot verify semantic correctness or ensure no SEO equity is lost through misconfiguration.

We manually inspect every entry to confirm the source path matches the intended destination and that the HTTP status code (usually 301) is appropriate. A single erroneous redirect breaks navigation for returning visitors or dilutes domain authority. We also verify that no sensitive parameters are stripped or exposed during the transition. The agent may propose a list of potential redirects, but only a human can confirm the logic holds against the actual site structure and business rules.

## Claims worksheets and empty-cite gates as publish blockers

A dry build is not a published article; it is a draft of facts awaiting proof. Before any content leaves the local machine, every factual claim must map to a verifiable source. If an agent generates a statement regarding historical events, scientific data, or financial figures without a corresponding citation, that entry acts as a publish blocker.

We use claims worksheets where each assertion is tagged with a requirement for evidence. An "empty-cite" gate prevents the final build from proceeding if any mandatory reference is missing. This is about integrity. Without these gates, the system risks propagating hallucinations or outdated information into the live environment. The agent can draft the text, but it cannot validate the truth value of the statements within that text.
